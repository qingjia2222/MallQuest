## 1. 环境变量配置

### 现象

最初只把真实配置填进了 `server/.env.example`，不知道下一步做什么。

### 原因

`.env.example` 只是配置模板，程序真正读取的是 `server/.env`。模板也不应该长期保存真实密钥。

### 解决方法

在 `server` 目录中复制模板为 `.env`，把以下真实配置只保存在 `.env`：

```text
LLM_API_KEY
WX_APP_ID
WX_APP_SECRET
```

`server/.env` 已被 `.gitignore` 忽略，不会正常提交到 GitHub。当前代码中的 `.env.example` 保持空值或占位值。

## 2. Python 与启动环境

本项目所有 Python 命令使用：


## 3. `run_demo.ps1` 双击后被记事本打开

### 原因

Windows 把 `.ps1` 文件关联到了记事本。直接双击只会查看脚本，不会执行。

### 正确启动方式

在项目根目录空白处按住 `Shift` 点击鼠标右键，选择“在终端中打开”，执行：

```powershell
cd "E:\shixi\llm\小组作业2"
powershell -ExecutionPolicy Bypass -File .\run_demo.ps1
```

看到以下信息表示启动成功：

```text
Backend: http://127.0.0.1:8000
Web: http://127.0.0.1:5173
```

启动窗口需要保持开启。不要为了双击运行而修改系统级 PowerShell 文件关联或执行策略。

## 4. 后端是否启动：正确筛查顺序

### 第一步：健康检查

浏览器打开：

```text
http://127.0.0.1:8000/health
```

看到 `code: 0` 和 `status: up` 说明 8000 端口上有后端服务。

### 第二步：确认是不是最新后端

仅仅 `/health` 正常还不够，因为旧版后端也有健康接口。打开：

```text
http://127.0.0.1:8000/docs
```

确认接口列表包含：

```text
POST /api/auth/phone-login
```

如果健康检查成功，但手机号登录返回 404，说明 8000 端口运行的是旧后端，而不是密码错误。

### 第三步：查找占用 8000 端口的进程

```powershell
netstat -ano | Select-String ':8000'
```

找到 `LISTENING` 行最后一列的 PID。先验证进程：

```powershell
Get-Process -Id <PID>
```

确认它是本项目启动的 Python 后端后再停止：

```powershell
Stop-Process -Id <PID>
```

随后重新运行 `run_demo.ps1`。不要在未确认进程身份时随意结束其他进程。

## 5. 手机号登录 404

### 报错

```text
POST http://127.0.0.1:8000/api/auth/phone-login 404 (Not Found)
```

### 实际原因

8000 端口曾被旧版 FastAPI 进程占用。旧进程的 `/health` 正常，但没有新的手机号登录路由。

### 已验证的解决方法

1. 停止旧 Python 后端。
2. 使用当前仓库重新启动 FastAPI。
3. 打开 `/docs` 确认存在 `/api/auth/phone-login`。
4. 使用演示账号重新登录。

游客/会员演示账号：

```text
手机号：11111111111
密码：123456
```

修复后真实 HTTP 请求已经返回 `code: 0` 和 `login_channel: phone`。

## 6. `mall.db` 被锁定，Pytest 无法删除数据库

### 报错

```text
PermissionError: [WinError 32]
另一个程序正在使用此文件
```

### 原因

正在运行的 FastAPI 持有 SQLite 数据库连接，而自动测试中的 `reset_and_seed()` 需要删除并重建 `server/data/mall.db`。Windows 不允许删除正在被其他进程使用的文件。

### 正确测试顺序

```text
停止后端
→ 运行 pytest
→ 运行 smoke_demo.py
→ 测试结束
→ 再启动后端
→ 进行开发者工具演示
```

如果后端在可见 PowerShell 窗口中运行，进入该窗口按 `Ctrl+C`。然后执行：

```powershell
D:\miniconda\Miniconda3\envs\OpenCV\python.exe -m pytest server/tests -q
```

本次释放文件锁后，测试结果为：

```text
14 passed
```

文件锁不影响正常演示，只影响需要重置数据库的自动测试和初始化脚本。

## 8. GitLens 与 GitHub 登录弹窗

### 现象

开发者工具编辑器中的 GitLens 询问是否连接 GitHub，以及是否打开父目录中的 Git 仓库。

### 结论

点击 `Yes` 并登录 GitHub 不会影响小程序运行。它只是编辑器 Git 扩展的仓库集成功能，与微信登录、后端鉴权和小程序编译无关。

## 9. 微信登录出现 `invalid code`

### 原因

`wx.login()` 返回的 code 是一次性且短时有效的，还必须与正确的 AppID/AppSecret 配对。旧 code、AppID 不匹配或开发者工具项目身份不正确都会导致 `invalid code`。

### 当前解决方案

游客 UI 已按需求改为手机号和密码登录，不再依赖微信 code 完成演示。真实 `/api/auth/wx-login` 和 `code2session` 适配仍保留，用于兼容和后续扩展。

## 10. 上传按钮是灰色的

### 原因

为避免 GitHub 再次扫描出 AppID，公共的 `app/project.config.json` 使用：

```json
"appid": "touristappid"
```

游客 AppID 可以编译，但不能上传。当时本地 `project.private.config.json` 又没有真实 AppID，所以“上传”按钮变灰。

### 已验证的解决方法

运行：

```powershell
D:\miniconda\Miniconda3\envs\OpenCV\python.exe server/scripts/configure_wechat_project.py
```

该脚本从被忽略的 `server/.env` 读取 `WX_APP_ID`，写入同样被忽略的 `app/project.private.config.json`，不会打印或提交真实值。关闭并重新打开开发者工具项目后，真实 AppID 会覆盖 `touristappid`，上传按钮恢复。

## 11. 找不到版本号输入框

当时看到的是“导入/新建项目”窗口，不是“上传代码”窗口。项目导入界面没有版本号。

### 正确位置

1. 点击“直接打开”进入项目。
2. 在编辑界面右上角点击“上传”。
3. 上传弹窗中填写版本号和备注。

## 12. GitHub 邮件提示 Secrets Detected

### 邮件内容

GitHub 指向 `app/project.config.json` 中的 Tencent WeChat API App ID。

### 实际上传内容

上传的是微信小程序 AppID，不是微信 AppSecret，也不是千问 LLM Key。AppID 通常是客户端标识符，但 GitHub 会按腾讯凭证模式告警。

### 已完成处理

- 公共配置改为 `touristappid`。
- 真实 AppID 只写入被 Git 忽略的 `project.private.config.json`。
- `WX_APP_SECRET` 与 `LLM_API_KEY` 只保存在 `server/.env`。
- 固定 Token 签名字符串也已替换为随机本地值。
- 当前跟踪文件与本地真实凭证的匹配扫描结果为 0。

旧 Git 历史中的 AppID 没有改写，因为用户明确决定不做破坏性的历史重写。

## 16. 手机扫描开发版二维码提示已过期

### 报错

```text
开发版本小程序已过期，请在开发者工具重新扫码
```

### 原因

开发版或预览二维码有有效期，不适合作为永久商场二维码。之前保存的开发版码被微信判定过期。

### 当前最可靠的演示方式

1. 开发者工具选择“AI 服务二维码”编译模式。
2. 点击“编译”。
3. 点击顶部“预览”。
4. 用已加入该项目开发成员的微信立即扫描新预览码。

手机能打开游客/会员登录页，并保留 `QD-AI-DEMO` 场景，即证明“扫码拉起小程序”成功。演示前重新生成预览码即可，不需要提交审核或正式发布。

长期不易过期的固定服务码需要体验版或正式发布环境，这不属于当前课程演示的必要条件。

## 17. 手机扫码能进入，但登录提示后端未启动

### 实际原因

小程序当前 API 地址是：

```text
http://127.0.0.1:8000
```

在手机上，`127.0.0.1` 指向手机自身，不是开发电脑。因此即使电脑后端已经启动，手机也无法通过这个地址访问它。

### 当前演示边界

- 手机：验证扫码拉起和场景传递，停留在登录页即可。
- 微信开发者工具模拟器：完成手机号登录、问答、规划、路线、事务和 TTS 等完整演示。

如果未来要让手机跑完整链路，需要把 API 地址替换为手机可访问的 HTTPS 地址，并在微信公众平台配置合法域名，然后重新预览或上传。

## 18. `res.scrollTo is not a function`

### 报错

```text
TypeError: res.scrollTo is not a function
```

### 原因

旧代码通过 SelectorQuery 获取的是节点结果包装对象，却直接调用了 `res.scrollTo()`；当前小程序基础库中该对象没有这个方法。

### 已完成修复

聊天页面改为使用 `scroll-view` 的 `scroll-top` 数据绑定和 `scroll-with-animation`，不再调用节点方法。修复后 JavaScript 语法检查通过。

## 19. AI 回复显示 JSON 代码框

### 现象

对话结果、会员积分等信息曾直接显示 JSON 对象，像开发调试输出，不适合演示。

### 解决方法

前端改为按业务字段渲染中文文本和富卡片：会员中心展示积分、等级和有效期；对话展示回复与对应业务卡片，不再把整个响应对象序列化到黑色代码框中。

## 20. AI 回复出现 `**文字**`

### 原因

在线 LLM 返回了 Markdown 粗体标记，而小程序文本组件没有渲染 Markdown，导致星号直接显示。

### 已完成的三层处理

1. 系统 Prompt 明确禁止星号和 Markdown 粗体。
2. 后端统一移除 AI 回复中的 `*`。
3. 小程序和 Web 显示层再次清洗星号。

自动测试已验证 `**木棉亲子餐厅**` 会显示为普通的“木棉亲子餐厅”。

## 21. 演示输入区不需要预设快捷标签

停车、积分规则、特惠等快捷标签已从演示输入区移除，现场由演示人员自己输入问题，避免界面像固定脚本菜单。

## 22. 地点问答需要自动弹出地图路线

### 当前行为

只有明确导航意图，例如：

```text
从当前位置怎么去电影院？
怎么去蜀香小院？
```

才会触发 `route_animation`：背景暗化、地图浮层、小红点移动、跨楼层提示、重播和关闭。

停车、积分、优惠和普通攻略不会误弹地图。路线由后端 Dijkstra 图计算，不是预制视频。

二维码场景还会把入口节点写入会话，作为“您当前所在位置”。

## 25. 微信开发者工具安装错误 `0x80570004`

安装阶段曾出现该错误，最终开发者工具已经成功安装并可编译、上传和预览。若再次出现，推荐按以下顺序处理：

1. 结束残留的微信开发者工具和安装程序进程。
2. 从微信官方渠道重新下载 Stable 完整安装包。
3. 确保系统盘和安装盘有足够空间。
4. 将安装包复制到不含特殊字符的短路径后，以管理员身份运行。
5. 若仍失败，删除损坏的临时安装包后重新下载，不要反复运行同一个缓存安装文件。

这类错误属于安装器或本机环境问题，与 MallQuest 项目代码无关。
