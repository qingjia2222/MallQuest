# 整轮需求闭环审计

审计日期：2026-08-31。本文核对本轮用户补充、`mission.md` 和甲乙整合要求；业务功能以自动测试、构建和实机前静态检查为证据。

## 身份与入口

- 启动页为游客/会员、商户、商场管理者三个独立入口，进入后只显示本角色工作区，退出才返回入口。
- 游客端改为手机号密码登录，演示账号 `11111111111 / 123456`；商户继续使用店铺编码，管理者继续使用管理账号。
- AI 服务二维码支持 `pages/scan/scan?scene=QD-AI-DEMO`，扫码后绑定当前商场私有数据源并拉起游客链路。

## 甲乙双端融合

- 商场品牌、首页/对话/规划/我的四栏和 3D 地图视觉统一采用甲方“星河里”版本。
- Web 与微信小程序使用同一 FastAPI、SQLite、会话、店铺、状态和路线数据；不再各自维护互相矛盾的店铺结果。
- 小程序对话补齐 Web 的方案卡、双策略、显式确认、预约/购票选择、同屏地图路线、重播/关闭和返回上下文。
- AI 回复在后端与小程序端清理原始 Markdown 星号；Web 将合法加粗语法渲染为富文本，不裸露 `**`。

## 店铺、商户与管理端

- 甲方地图的 22 个店铺与后端 22 条业务店铺统一绑定；营业、排队、余位、优惠均读取同一数据源。
- 店铺编码显示在游客店铺详情楼层旁，可通过编码查询和导航；商户凭编码进入自己的店铺并更新实时状态。
- 管理端修复头部按钮重叠，移除“经营数据明确标记为 MOCK”文案和“平面图数字化”界面，同时保留店铺编码与经营分析能力。

## LLM、规划与事务

- 保留千问 OpenAI-compatible 适配器、工具注册表、Function Calling、RAG、会话槽位、显式 Planner 状态机和 scripted 兜底。
- 约会、家宴、礼物、带娃、商务五场景均提供“用时最短”和“路程最近、回头路最少”两种方案。
- 固定权重写入后端：fastest = 等候 1.0 + 步行 1.0 + 换层 2.0 + 超预算 0.03；shortest = 距离 1.0 + 重复路段 2.0 + 换层 25.0 + 排队 0.0。
- 选择策略后，行程、路线、地图动画、预约、领券和购票使用同一组选中店铺；未被选中的店铺不会被执行事务。

## 地图与导航

- 只有明确找目的地/问路触发沉浸式路线动画；普通攻略、积分和优惠问答不自动弹图。
- 后端使用 Dijkstra 路网，店铺终点落在临走廊入口；路线仅允许 corridor、store_entrance、elevator、escalator 节点，不使用可能穿墙的店铺中心直线兜底。
- 跨层同时提供直梯和扶梯，可在方案或导航中切换；指令、路线节点和 3D 动画同步变化。
- Web 使用甲方 Three.js 地图；微信端使用原生 WebGL 轻量 3D，并保留设备不支持 WebGL 时的明确降级界面。
