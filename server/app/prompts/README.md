# 提示词维护目录

运行时系统提示词集中存放在这里，不写进业务路由或页面代码：

- `system.md`：角色、安全边界和统一输出规则。
- `tool_router.md`：普通对话的只读工具选择规则。
- `planning.md`：场景方案与 Planner 输出约束。

以上三个文件是当前在线 LLM 请求实际读取、也是管理端白名单开放维护的运行时提示词。`planning.md` 已包含活动角色、早餐/午餐/下午茶/晚餐/夜间休闲、多样性校验和非商户 POI 规划契约；保存后 Web 与微信小程序会通过共用后端同时生效。

目录中的 `intent_slots.md`、`planner.md` 是早期拆分方案保留的参考文件，当前运行链路不读取；`rag_answer.md` 也是早期回答模板，现行 RAG 使用检索器的确定性无证据提示与工具路由，不读取该文件。它们不出现在管理端，避免管理员误改无效文件。若未来重新接入，必须先增加运行时读取点和回归测试，再加入 `PROMPT_FILES` 白名单。

管理端“系统提示词维护”通过受权限保护的 `/api/manager/prompts` 接口编辑这些白名单文件。保存时必须携带当前版本号，防止多人覆盖；旧版本会自动备份到 `backups/`。下一次 LLM 请求会读取新内容，无需改数据库或重启服务。

规划采用“LLM 提候选结构 → 后端校验店铺与路线 → 基于 canonical plan 展示”的契约。模型不得另写一套与 `PLAN_JSON` 不同的行程；自然语言增删地点、替换、重排、改时间/人数/预算和路线策略必须反映到结构化字段中。这样保留 LLM 的开放式理解能力，同时保证最终文案、方案卡、地图路线与事务执行一致。

不要在提示词中写 API Key、密码、手机号等秘密或个人数据。业务事实仍必须来自 SQLite、工具和 RAG，提示词不能替代业务数据。
